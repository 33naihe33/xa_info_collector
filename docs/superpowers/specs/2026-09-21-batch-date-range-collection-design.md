# 批量日期范围抓取设计

## 目标

在“信息源状态”页面提供一次性批量抓取：用户可勾选多个已启用信息源，并指定必填且包含边界的开始、结束日期。系统仅入库发布日期在闭区间内的文章。

现有逐行“立即抓取”保持不变，仍执行原有增量抓取。

## 用户交互

1. 用户在信息源状态页点击“按范围抓取”。
2. 弹窗展示所有已启用信息源，支持全选、取消全选及多选。
3. 用户填写开始日期、结束日期；两项必填，开始日期不得晚于结束日期。
4. 提交后页面提示后台任务已启动及选中的信息源数量，并刷新数据源统计。
5. 接口校验失败、已有抓取任务运行或后台任务启动失败时，页面展示明确错误信息。

未启用的信息源不会出现在可选项中。单行“立即抓取”继续仅针对该行信息源执行不带日期范围的增量抓取。

## 后端设计

新增批量抓取 API，接收 `sources`、`date_from`、`date_to`。成功时返回已接受的信息源数量，前端以该返回值提示任务规模。它将在入队前完成以下校验：

- `sources` 非空、去重后均为已知且已启用的信息源；
- 日期符合 `YYYY-MM-DD`，且 `date_from <= date_to`；
- 复用现有 collect 锁；锁已持有时返回 HTTP 409，不创建任务。

请求体结构不合法由 FastAPI 返回 HTTP 422；业务校验（空选、未知/未启用源、日期倒置）返回 HTTP 400，并附带可展示的 `detail`。

后台任务依次构造并运行每个 adapter，不并发访问目标站点。一个信息源失败时记录日志并继续执行余下信息源；锁始终在任务结束时释放。

批量范围任务持有 collect 锁期间，定时增量抓取会按现有机制跳过并记录日志；这属于单锁互斥的预期行为，任务结束后的下次调度会自动恢复增量抓取。宽日期范围配合多个信息源可能运行较久。

为支持严格上界，`BaseAdapter.run` 扩展为接受可选的 `until` 参数。`until is not None` 明确表示范围运行；范围 API 始终同时传入 `since=date_from` 与 `until=date_to`。它继续把 `date_from` 传给 adapter 的列表抓取逻辑以减少请求，并在详情抓取前，将列表项发布日期归一化为 `YYYY-MM-DD` 后统一过滤：只处理 `date_from <= publish_date <= date_to` 的条目。发布日期缺失或无法归一化的条目不纳入范围任务，避免违反用户选择的时间范围。

范围运行跳过所有 `_retry_pending` 调用。pending URL 没有经过列表页日期边界验证，不能在范围任务中被重试并入库；它们仍留待后续普通增量运行处理。

`XionganPortalAdapter` 自行覆写了 `run()` 和栏目级 `_run_category()`，因此必须同步扩展两个签名与调用链：范围运行跳过全局和栏目 pending 重试，并在每个栏目详情抓取前应用同样的日期归一化与闭区间过滤。

## 增量游标规则

范围抓取是补抓操作，不能改变日常增量抓取的起点。因此当 `until is not None` 的范围运行时：

- 仍会生成 `crawl_runs` 审计记录与计数；
- 无论成功、部分失败还是失败，均写入 `last_crawled_date=None`，绝不把用户的 `date_from` 或本次发现的最新日期写为增量游标；
- 现有 `run()`（无日期参数）行为保持不变。

文章去重、失败重试、站点 QPS 限制、图片处理及 CrawlRun 状态沿用现有基础设施。

## 前端设计

`SourceStatus.vue` 增加一个主操作按钮和 Element Plus 弹窗：

- 多选数据源清单显示数据源名称；
- 起止日期使用日期选择器，禁止提交不完整或倒置区间；
- 提交期间禁止重复提交并显示加载态；
- 成功后关闭弹窗并延迟刷新列表；失败时从 API 响应提取可读提示。

Pinia store 和 API client 增加对应的批量方法与加载状态，现有单源方法及调用方不变。

## 信息源历史范围限制

日期范围是对系统实际发现到的文档进行严格筛选，不等于网站可任意回溯。部分源只公开当前列表页或有限分页；若选定日期内的历史文章不在可访问页面中，系统不会伪造、猜测或抓取到它们。部分列表页不提供发布日期，或日期无法解析；这些条目在范围运行中会被跳过，结果可能为零。任何成功入库的文章都必须处于用户指定日期闭区间内。

## 验证

- 后端：验证空选、未知/未启用信息源、非法日期、倒置区间和抓取锁冲突均被拒绝。
- 后端：mock 多个 adapter，验证顺序执行、每个 adapter 收到正确边界、一个失败不阻断其他源、最终释放锁。
- 采集核心：验证范围上下界均包含、范围运行跳过 pending 重试而不入库范围外旧条目、发布日期缺失或无法归一化的列表条目不入库。
- 游标：验证范围运行成功、部分失败及失败三种路径均不推进或回退正常增量游标；雄安官网栏目级游标同样保持不变。
- 前端：TypeScript 类型检查与生产构建通过；现有单源立即抓取回归正常。
